# ROADMAP.md — remaining phases (7–10)

Based on the authoritative phase prompts (kept outside the repo) and the
actual state in [PROGRESS.md](PROGRESS.md). Phases 1–6 are complete; nothing
below is implemented. Each phase starts only on explicit instruction, ends
with focused commit(s), and must pass fmt/clippy/test gates.

## Phase 7 — Git staged files & selective synchronization (`sync --staged`)

**Objective:** operate on files relevant to the Git *index* (staged state),
not the working tree.

Key requirements from the prompt:
- Git repository detection + root resolution; structured error when absent.
- Analyze the **index** state: staged content, never the working-tree
  version. Deleted/renamed staged files handled; rename support only when
  the API is reliable, otherwise remove+create.
- **`SourceInput` abstraction** (filesystem | in-memory content) so the
  existing oxc parser consumes staged content without knowing about Git;
  no second parser, no duplicated sync logic — converge into the existing
  pipeline early.
- Correctness invariant: staged sync ≡ clean analysis of the staged project
  state; fall back to full staged analysis when incremental correctness
  can't be guaranteed (uncertain renames, config changes, unsupported
  change types).
- Reuse Phase 5 ownership/conflict rules unchanged; never modify the Git
  index/HEAD/branches; dry-run support; unrelated staged files ignored
  silently-ish; empty relevant staged state is a clean no-op message.
- Git access: prefer a mature Rust library (e.g. `git2`) over shelling out;
  document the choice; one explicit Git-path↔OS-path normalization layer;
  treat repo paths as untrusted (traversal, symlinks, Unicode, duplicates).
- Tests: unit (status classification, path normalization, filtering) +
  integration in temporary Git repos (staged add/modify/delete/rename,
  unstaged-ignored, idempotence, dry-run writes nothing, conflict
  preservation, staged-vs-clean equivalence). Isolate from the user's real
  repo.

Likely touch points: new `src/git/` (or `src/staged/`), `src/nest/mod.rs`
(input abstraction), `src/commands.rs` + `src/cli.rs` (`sync --staged`),
`src/error.rs` (Git-specific error variants), docs/phases/phase-07.md.

## Phase 8 — Production hardening, CLI UX & release readiness

**Objective:** no new features; make what exists reliable for release.
- Feature audit of every subsystem; CLI quality/exit-code contract review
  (currently 0/1/2/3/4); diagnostics that answer what/where/why/what-now.
- Configuration hardening & precedence; filesystem security audit (paths,
  symlinks, atomic writes, deletions); watch-mode hardening under realistic
  editor behavior; Git integration hardening (detached HEAD, empty index,
  Unicode paths, changes during execution).
- Performance audit with benchmarks where practical (none exist in-tree —
  first one lands here); memory review of long watch sessions.
- Cross-platform review (Windows/macOS untested; watch e2e Unix-only);
  dependency audit (`cargo tree`); unsafe review (none expected);
  documentation accuracy pass.
- Release items: `cargo build --release` validation, Cargo metadata
  (note: **no LICENSE chosen yet** — owner decision blocking publication),
  release checklist, installation validation. Version stays 0.1.0 unless a
  release policy says otherwise.

## Phase 9 — Advanced route semantics & request metadata

**Objective:** richer Bruno requests from *static* information only.
- Extend the existing route IR (no duplicate models): parameter locations
  (path/query/header/body), named vs unnamed, statically visible path
  parameters from the route path, basic type metadata when trivially
  available (string/number/boolean/DTO name), minimal local DTO property
  extraction; no recursive type resolution, no tsc, no evaluation.
- Bruno representation updates within the verified format; metadata must
  not destabilize route identity or break Phase 5 sync/Phase 6 watch
  (metadata change ⇒ update in place, not delete/create); backward
  compatible with files generated by phases 4–6.
- Tests: parser (each decorator × named/unnamed × types × dynamic),
  generator golden tests, integration incl. sync/watch compatibility.

## Phase 10 — OpenAPI interoperability

**Objective:** export the existing route IR to OpenAPI (prefer 3.1); optional
`openapi validate --spec <file>` comparison; consume the IR, never reparse.
- Deterministic document (stable ordering, no timestamps), config for
  title/version/description/servers; `:id` → `{id}` reusing existing
  normalization; operationIds from controller+handler+method+path with
  deterministic collision handling; conservative parameters/schemas/
  responses (default response when nothing is known); no network, no `$ref`
  fetching, no execution.
- CLI per existing conventions; YAML and/or JSON output; golden tests;
  security tests (traversal, malicious specs); must not regress Bruno
  generation (same IR feeds both).
