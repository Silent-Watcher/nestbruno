# Phase 9 — Advanced route semantics & request metadata

**Status: Completed (2026-11-08).**

## What was built

Richer Bruno requests from *static* information only, without destabilizing
route identity or breaking Phase 5 sync / Phase 6 watch.

### Route IR extensions (`src/route.rs`)

- `RouteParameter.type_name: Option<String>` — the parameter's type annotation
  when it is one plain identifier: a keyword (`string`, `number`, `boolean`)
  or a bare class name (`CreateUserDto`). Arrays, generics, unions, qualified
  names, intersections, parenthesized types — anything beyond one identifier —
  are `None`. Never guessed, never evaluated.
- `BodyShape` enum on `Route.body`:
  - `None` — no `@Body` parameter, the request has no body.
  - `Unknown` — a body is accepted but its fields could not be determined
    statically (no type annotation, or the type is not a same-file class).
  - `Fields(Vec<String>)` — property names of a same-file class/interface
    matched by the body parameter's type annotation, in source order.

### Extractor (`src/nest/extract.rs`)

- `extract_type_name()` maps an AST type annotation to the simple name above.
- `dto_properties()` collects property names of every top-level class **and
  interface**, keyed by name. Computed keys are skipped, methods and
  constructors ignored, at most 64 properties per class (`MAX_DTO_PROPERTIES`).
- `resolve_body_shape()` combines the `@Body` parameter's type with the DTO
  table: `None` when no body param, `Fields` when the type names a same-file
  class with properties, `Unknown` otherwise.

### Bruno generation (`src/bruno/model.rs`)

- `BodyShape::Fields` produces a JSON skeleton with one `null` per DTO
  property, merged with any named `@Body('field')` parameters (deduplicated).
- `BodyShape::Unknown` produces `{}` (plus named body fields when present).
- `BodyShape::None` produces `body: none`.
- Parameter type metadata is recorded in the `docs` block as
  `@Kind(name): type TypeName` lines (sanitized via `display()`).
- The "whole object, fields not inferred" note is only emitted for
  `@Body()` when the body shape is actually `Unknown`.

### Identity & compatibility

- Route identity (`bruno/identity.rs`) is unchanged: controller + method +
  path + handler. Metadata changes never alter identity, so a DTO edit
  updates the request **in place** (UPDATE, not DELETE+CREATE). Verified by
  integration tests in `tests/sync.rs`.
- Backward compatible: files generated by phases 4–6 are recognized by sync
  (the stamp hash changes only because the content changed, which is the
  normal update-in-place path).

## Tests

- Parser: each decorator × named/unnamed × types × dynamic (keywords, bare
  identifiers, generics, arrays, unions, qualified names, parenthesized,
  type arguments) — 8 new extractor tests.
- DTO extraction: class properties in source order, interface properties,
  computed keys skipped, methods/constructors ignored, 64-property limit,
  unknown DTO → `Unknown`, no body → `None`, named body + DTO combination —
  8 new extractor tests.
- Generator: `BodyShape` → body mapping, named body params merged with DTO
  fields, type metadata in docs — 4 new model tests.
- Integration: DTO added/removed/renamed updates in place (3 new sync tests).
- Golden fixtures regenerated (`tests/fixtures/expected-bruno/`).
- Hostile-source test updated: `script:` block detection now checks line
  starts (sanitized param names in docs may contain "script" as a substring).

Total: 495 tests (was 471), fmt + clippy `-D warnings` green.

## What was NOT done (out of scope)

- No cross-file DTO resolution (would need project-wide type resolution).
- No recursive type resolution, no `tsc`, no evaluation.
- No field-level type annotations in the JSON skeleton (all `null`).
- No OpenAPI output (Phase 10).
